## 二、真值结构

每条真值一个文件：`data/fixtures/truth/<fixture>.json`。

```json
{
  "fixture": "case.zip",
  "expected_findings": [],
  "expected_collisions": {
    "windows": [{"code": "collision.CASEFOLD", "survivor": "README.TXT"}],
    "macos": [],
    "linux": []
  },
  "expected_accessibility": {
    "windows": {"Readme.txt": "OK", "README.TXT": "OK"},
    "linux": {}
  }
}
```

三条结构纪律：

1. **只存输入与期望**：禁止出现 `observed_*` 一类字段（`plan` 的"真值库禁观测"条已实测过它的代价——引擎全坏也全绿）。
2. **期望值可由输入独立复算**：`expected_*` 的每一项都必须能从 fixture 字节 + 平台表推出，不依赖被测实现。
3. **空 = 必须有**：`expected_collisions.windows: []` 表示"必须一条都不报"，与"没写这个键"是两件事——测试按"键存在性"区分（缺键 = 真值不完整，红）。

## 三、真值纪律（对账怎么跑）

| 断言的层级 | 位置 | 说明 |
|---|---|---|
| fixture ↔ 真值一一对应 | `tests/test_fixtures.py` | 无孤儿、无缺真值；生成器 `PENDING` 与目录内容一致 |
| 重生成逐字节一致 | `tools/gen_fixtures.py --check` + 同一测试 | **两层**：盘上产物形态 + 重生成结果（只测前者时生成器改坏也能绿） |
| 判定结果对账 | 各模块测试（M2 起） | 读真值 → 跑模块 → 逐 `ruleId` 比较；**用集合比较，逐条点名差异** |
| 零误报基线 | `tests/test_fixtures.py::test_clean_has_no_findings` | `clean.zip` 必须 0 finding（M2 起生效，骨架期断言真值为空） |

## 四、落库节奏

| 里程碑 | 落库内容 | 提交要求 |
|---|---|---|
| M0 | 6 份 fixture + 真值 + 生成器 | 生成器可 `--check`；真值成对 |
| **M1（已收口）** | 其余 16 份 fixture + 真值 + `$UpCase` 表 + 四工具对照矩阵 + `docs/rules.md` 骨架 | `--check` 逐字节一致（22/22）；表带卷标识、探测环境、sha256 与 8 组真实卷校验记录；矩阵 22×4 格每格有命令与输出节选，且重跑一致 |
| M2–M5 | 判定结果纳入回归（fixture 不再新增，除非新发现形态**追加在末尾**） | 新样本追加，不改既有样本（保持既有确定性序列） |
| M6 | 无新增数据 | 指标与样例回填 README |

**"追加在末尾"的理由**：既有 fixture 的顺序参与确定性序列（`fixtures` 列表的字典序 + 真值文件名），
中途插入会改变既有快照的 diff 噪声。这是本项目自定口径（K06），改动要在 `plan/05` §K 清单里同步。

## 五、数据界的"不确定"处理

| 情形 | 处理 |
|---|---|
| 某平台行为未实测（macOS/Linux 落盘） | 输出标 `table_simulated`，**不得**写成 `measured` |
| APFS 依据中硬 | 输出 `evidence_strength: medium` + `docs/rules.md` 写明"非 Apple 官方规范" |
| APPNOTE 官方原址不可达 | 引用时写清镜像来源（`bearcove/rc-zip` `static/appnote.txt` v6.3.10） |
| ODF 尾随换行未明文禁止 | 输出 `inferred: true` |
| `$UpCase` 表来源不可追溯 | `platforms --verify` 报 `platform_table_missing`（退出码 3），**不静默使用** |
