## 三、门验证（本项目的门自己也要能变红）

### 3.1 布局门变异（10 组，逐组必须红；见 `tools/check_sprint_layout.py` 文件头）

| 组 | 变异 | 期望变红的判据 |
|---|---|---|
| M1 | 删 `AGENTS.md` | `LAYOUT.FILES` |
| M2 | 一个副本里把某 ✅ 翻成 ⬜ | `LAYOUT.STATUS` |
| M3 | 缺口格写回已 ✅ 的里程碑 | `LAYOUT.GAPS` |
| M4 | 删一份 `HANDOFF-M<k>` | `LAYOUT.HANDOFFS` |
| M5 | 删 `plan/00` 顶部装订行（整行移除） | `LAYOUT.BINDING_HEAD` |
| M6 | 删发布留档「覆盖对账」整节 | `LAYOUT.RELEASE` |
| M7 | 删一份 `plan/0<k>` | `LAYOUT.FILES` |
| M8 | 去掉发布留档 §二标题的 "tag 后" | `LAYOUT.RELEASE` |
| M9 | 台账一条 ✅ 行改成 `⬜ 待 M<k>` | `LAYOUT.LEDGER` |
| M10 | 发布里程碑 ✅ 留着但删 `RELEASE-M<last>` | `LAYOUT.RELEASE` |

**M6/M8/M10 的三条互不替代**：`LAYOUT.RELEASE` 里有两个独立判据（覆盖对账小节 / 两栏），
再加"未完成即跳过"分支的反向——**一条门里有几个判据，变异就要覆盖几个**。

### 3.2 脱敏门变异（4 组）

| 组 | 注入 | 期望规则 |
|---|---|---|
| V1 | 文档里写 `D:/ProgramData/<x>` | `absolute-path` |
| V2 | 写 `C:\Users\<真实用户名>\x` | `absolute-path` + `host-username` |
| V3 | 写 `/c/Users/<真实用户名>/x` | `msys-user-path` |
| V4 | 写 `<本机回环IP>:<端口>`（真实回环代理端口） | `loopback-proxy` |

还原后必须复绿；命中时逐行点名 `文件:行: [规则]`。

**M0 变异状态**：`LAYOUT.STATUS` / `LAYOUT.HANDOFFS` / `LAYOUT.GAPS` / `LAYOUT.LEDGER` / `LAYOUT.RELEASE`
的五组在 M0 只有弱形态（M0 是唯一 ✅ 里程碑，且被显式豁免 HANDOFF；`RELEASE-M6` 尚不适用）。
**这五组要在 M1/M2 里程碑落地后按当时仓库形态复跑**——"本轮绿"不等于"每条判据都被证伪过一次"，
这句话在本项目里的落地形式就是本表。

## 四、发布流程（M6）

1. `py -3.12 tools/gen_fixtures.py --check` + 全量 `pytest` + 布局门 + 脱敏门（本地等价校验）。
2. 定版：`__version__` 从 `0.1.0` 提到 `1.0.0`（或按实际），同提交重生成所有含版本指纹的样例。
3. `scripts/build.py` → `dist/extract-oracle.exe`；在**干净目录**跑 native 冒烟。
4. 写 `plan/RELEASE-M6.md`（**tag 之前**落盘）：§一 tag 前事实 / §二 tag 后追加事实（先落占位骨架）/ §三 阶段 7 覆盖对账表。
5. `git tag -a v1.0.0` → push → `gh release create v1.0.0 dist/extract-oracle.exe --notes-file …`。
6. `gh release download` 回下载件 → sha256 对账 → 原生冒烟。
7. tag 后只允许**非交付面**提交（`plan/` `tests/` `tools/` `docs/` `README` `AGENTS`），交付面（`src/` `scripts/` `data/fixtures`）零差异。

**自指约束**：`plan/RELEASE-M6.md` 在 tag 树内，**不得**写 tag OID / 本包 sha256 的字面值；字面值只写进 tag 后的提交或 Release 正文。
