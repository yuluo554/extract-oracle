# 02 · 架构与技术选型

> 上游：`plan/01-题目文档.md` §2（五模块）｜状态副本与里程碑见 `plan/00` §六
> 本文只定**分层、边界、数据契约、构建链路、错误降级、确定性设计**；判定口径的数值只在 `data/README.md` §4 定义。

## 一、分层

```
                ┌──────────────────────────────────────────┐
   CLI 入口 ───► │ cli.py（argparse / 退出码 / 机读错误行）   │
                └───────────────┬──────────────────────────┘
                                │
        ┌───────────────────────┼────────────────────────┐
        ▼                       ▼                        ▼
  archive/（字节层）      rules/（判定层）           report/（导出层）
  zip_reader.py          structure.py  MOD-1       report.py
  tar_reader.py (扩展)    encoding.py   MOD-2       render_text / dumps_json
                         fold.py       MOD-3       （确定性 + 原子写）
                         access.py     MOD-4
                         container.py  MOD-5
                                │
                                ▼
                        platforms.py（表访问，包根叶子）
                                │
                                ▼
                        data/platforms/（平台语义表）
                        ntfs-upcase.bin + meta.json
```

**`platforms.py` 为什么在包根而不是 `rules/`**：它做的是**数据访问**（读字节 + `sha256` 对账 +
逐码元查表原语），不是判定。放 `rules/` 会让每个需要表（或共享 `Collision` 形状）的判定模块都
import 它——那是"判定模块互相 import"的字面形态，K10 的 AST 守门会（正确地）变红。
`findings.py` 的先例同理（M2 立，M3 复用）。

**四条硬边界**（每一条都有对应的测试，见 `plan/03`）：

| 边界 | 含义 | 为什么 |
|---|---|---|
| 字节层不做判定 | `zip_reader` 只返回结构事实（偏移/长度/原始字节），不产出 `ruleId` | 判定口径要能单点替换（如平台表换版），混在解析器里就换不动 |
| 判定层不写盘 | `rules/*` 是纯函数：`(entries, platform_tables) -> findings` | 纯函数才能做"同输入双跑逐字节一致"的门 |
| 导出层是唯一写盘点 | 只有 `report.py` 的 `write_atomic` 碰文件 | 换子命令时写盘形态不会漂（K 口径 K03） |
| 平台语义表外置为数据 | `data/platforms/*`，代码不写折叠表字面量 | 真 `$UpCase` 表可达 100+ KB，且换版时必须能追溯来源 |

## 二、模块边界与依赖方向

- `cli → rules → archive`，**单向**；`rules` 不得 import `cli`，`archive` 不得 import `rules`（AST 守门断言）。
- `rules` 之间**不互相 import**：MOD-3 消费的是"名字集合"这个纯数据结构，不是 MOD-1 的模块（防环形依赖，也让 MOD-3 能在 MOD-1 未完成时用合成输入单测）。
- 平台表通过 `PlatformTables` 结构体**注入**（构造参数），不做模块级全局单例（同输入双跑要求线程/顺序无关）。
  M3 落地：`platforms.load()` 在 `cli.cmd_check` 里调用一次，把 `PlatformTables` 传给 `rules/fold.py::check`；
  `rules/fold.py` **不**自己读文件（判定层不碰 I/O）。`ORACLE_PLATFORM_DIR` 是**权威覆盖**——设了就用它，
  缺文件即拒（否则"设了环境变量却被静默回落到源码树"会让"表缺 → 退 3"的判据失效）。

## 三、构建与交付链路

| 步骤 | 命令 | 产物 | 备注 |
|---|---|---|---|
| 开发安装 | `py -3.12 -m pip install -e ".[dev]"` | 可编辑安装 + console script | 零运行时依赖（`dependencies = []`） |
| 测试 | `py -3.12 -m pytest` | — | 单测 + fixture 对账 + 确定性双跑 |
| 布局门 | `py -3.12 tools/check_sprint_layout.py` | — | CI layout job 的一条 step |
| 脱敏门 | `py -3.12 tools/check_desensitized.py` | — | 同上 |
| fixture 自检 | `py -3.12 tools/gen_fixtures.py --check` | — | 两层断言（盘上产物 + 重生成） |
| 打包 | `py -3.12 scripts/build.py` | `dist/extract-oracle.exe` | PyInstaller onefile，**不能交叉编译** |

**版本号单一真源** = `src/extract_oracle/__init__.py` 的 `__version__`；`pyproject.toml` 用
`dynamic = ["version"]` 读取它。构建期注入到产物（`extract-oracle --version`），三处一致由测试断言：
根模块 / 安装元数据 / 产物自报（M6 起）。

**PyInstaller 的确定性口径**（提前写死，避免 M6 才发现）：exe 含构建期 PE 时间戳，**同机两次构建
sha256 不同是设计如此**；发布对账因此分两情形——树一致才做哈希强对账，换机构建只验结构口径
（附件名齐备 / 产物自报版本 / 原生冒烟）。这与"打包确定性"是两个命题，不得混写。

## 四、平台语义表的数据契约

`data/platforms/meta.json`（人工可读的元数据）+ `data/platforms/ntfs-upcase.bin`（表本体）：

```json
{
  "ntfs_upcase": {
    "source": "volume_read | host_probe",
    "volume": {"serial_hex": "...", "label": "...", "ntfs_version": "..."},
    "probed_at_utc": "2026-10-21T00:00:00Z",
    "probe_host": {"os_build": "...", "arch": "..."},
    "entries": 65536,
    "sha256": "<hex>",
    "generator_version": "1"
  },
  "tables": {
    "macos": {"evidence_strength": "medium", "source": "libfsapfs + TN1150 + UAX #15"},
    "linux": {"evidence_strength": "measured", "source": "pathname(7)"}
  }
}
```

三条契约纪律：

1. **`source` 只能是 `volume_read` 或 `host_probe`**——`casefold` 不是合法取值（决策记录 ③）。
2. **`sha256` 必须与表本体逐字节对得上**；对不上 = 表被换过，报 `platform_table_missing`（退出码 3），不静默使用。
3. **`probed_at_utc` 是环境事实，不是判定输入**——它不进报告 digest（否则跨机复跑必红）。

**M3 落地形态**（`src/extract_oracle/platforms.py`，全部实跑过）：

- 校验顺序固定，任一项不过即 `platform_table_missing`：`meta.json` 可解析 → `ntfs_upcase` 必填键齐
  （`source`/`volume`/`entries`/`sha256`/`encoding`）→ `source` ∈ 枚举 → `entries` = 65536 →
  本体长度 = `entries × 2` → `sha256(本体) == meta.sha256` → 两张副表 `evidence_strength` ∈ §4.7 枚举。
- 表定位：`ORACLE_PLATFORM_DIR`（**权威覆盖**）→ 源码树 `../../data/platforms` → `sys._MEIPASS/data/platforms`
  （冻结态）→ `cwd/data/platforms`。错误 `detail` 里**不出现路径**（K03：报告不得含本机绝对路径），
  只给 `expected` 与 env 变量名。
- **两个输出面分开**：`to_report_dict()`（进 `check` 报告）**只含** `entries`/`sha256`/`source` 与副表强度；
  `verify_report()`（`platforms --verify` 诊断）**含** `volume` 与 `probed_at_utc`。所以第 3 条只需约束前者。
- `rules/fold.py` 不读盘：`cli.cmd_check` 在范围含 `fold` 时调 `platforms.load()` 一次，把表注入判定函数
  （见 §二）。表缺 → 走 `cmd_check` 的异常通路退 3，**不产出"零冲突"**。

第 2 条与第 1 条的正/反向靶子都在 `tests/test_fold.py`：
`test_platform_table_sha256_is_verified_byte_by_byte`（正向）、
`test_replaced_table_is_refused_not_silently_used`（改一个字节 → 拒）、
`test_illegal_source_value_is_refused`（`source: casefold` → 拒）、
`test_missing_table_dir_is_refused`、`test_check_refuses_when_platform_table_missing`（CLI 面退 3）。

## 五、错误降级（唯一映射表在 `errors.py`）

| 情形 | reason code | 退出码 | 绝不做什么 |
|---|---|---|---|
| 文件读不了 / 非 ZIP / 无 EOCD | `input_unreadable` / `eocd_not_found` | 2 | 不返回 `0`、不返回空 findings |
| 需要平台表但表缺/校验失败 | `platform_table_missing` | 3 | 不静默跳过该平台的折叠判定 |
| 判定模块未落地（骨架期 `check`） | `capability_missing` | 3 | 不输出"零 finding"冒充通过 |
| 参数非法 | `usage_error` | 4 | argparse 的 `SystemExit(2)` 统一转 4 |

> 第 2 行 M3 起有实物（`platforms.py`）+ 双向靶子（见 §四末）。"表缺"与"表被换过"是**同一档**
> （都是"我拿不到可信口径"），但 `detail` 分得开：前者给 `expected`/`env`，后者给两侧 `sha256`。

**机读面**：错误一律往 stderr 打**一行 JSON**（`{"error","message","exit_code","detail"}`），stdout 不产出半份报告。
这条是 CI 断言的对象，也是"依赖缺失不静默退化为通过"的落地形态。

## 六、确定性设计（同输入 + 同平台表 → 逐字节一致）

| 维度 | 决定 | 反例（会漂的写法） |
|---|---|---|
| 键序 | `json.dumps(sort_keys=True)` | 依赖 dict 插入顺序 |
| 数组序 | 按 CD 条目偏移升序；同偏移按原始名字节字典序 | 按文件系统遍历顺序 |
| 时间 | 输出**不含**时间戳 | `datetime.now()` |
| 路径 | 只输出归档内名字，**不输出本机绝对路径** | `str(path.resolve())` |
| 换行 | 恒 `\n`，结尾恒有换行 | 平台默认 `os.linesep` |
| 编码 | UTF-8，`ensure_ascii=False` | 默认 `ensure_ascii=True`（中文变 `\uXXXX`） |
| 数值 | 整数；不做浮点舍入 | 百分比浮点 |

守门 = `tests/test_report_determinism.py`：同输入双跑 → 两次字节串 `==`，且断言输出里不含盘符形态。

## 七、扩展项的技术预留（不进首期）

- TAR：`archive/tar_reader.py`，与 `zip_reader` 共用 `EntryView` 中间表示（名字原始字节 + 标志 + extra）。
- 嵌套归档：只读内存流（`io.BytesIO`），不落盘；递归预算上限写进平台表 meta。
- 右键菜单：只做 `scripts/` 下的薄壳，调用同一入口，输出仍是文本/JSON。

三者都**不得**改变首期五模块的判定口径——改口径要走 `data/README.md` §4 的单一真相源流程。
