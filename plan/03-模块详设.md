# 03 · 模块详设

> 五个模块的编号与 `ruleId` 前缀必须与 `plan/01` §2、`plan/00` §七一致；改编号或前缀 = 口径分叉。
> 数值口径（退出码 / 三级可访问性 / 折叠规则 / 容器五条 / 预算）**只在 `data/README.md` §4 定义**，本文只引用口径键。

## 0. 公共输入输出契约

```text
EntryView                        # archive 层产出的条目视图（不含判定）
  index: int                     # 0-based，CD 顺序
  lfh_offset: int                # LFH 记录起始偏移
  cd_offset: int                 # CD 记录起始偏移
  lfh_name: bytes                # 原始字节，不解码
  cd_name: bytes                 # 原始字节，不解码
  lfh_flags: int                 # general purpose bit flag
  cd_flags: int
  lfh_crc: int; cd_crc: int
  lfh_csize: int; cd_csize: int
  lfh_usize: int; cd_usize: int
  extra: tuple[ExtraField, ...]  # 已切分，未解释
  method: int
  lfh_span: tuple[int, int]      # [start, end) 物理区间，用于重叠判定

Finding                          # 判定层唯一输出形状
  ruleId: str                    # 前缀决定归属模块
  entryIndex: int | None
  lfhOffset / cdOffset: int | None
  lfhName / cdName: str | None   # 展示形（surrogateescape 可逆）
  message: str                   # 人读一句话，不含本机路径
  evidence: dict                 # 机读证据（口径键 + 具体值）
  precedent: str | None          # MOD-1 必填：实现选择来源，不引规范条文
```

**排序**：`findings` 按 `(cd_offset, ruleId)` 升序；`collisions` 按 `(min(cd_offset), code)` 升序。
**零误报基线**：`clean.zip` 必须产出空 `findings`（`plan/01` §2 模块⑤验收）。

## MOD-1 双头差分与重叠（M2）

**输入**：ZIP 字节。**输出**：`structure.*` 六条。

| `ruleId` | 判定 | 实现要点 | 误报控制 |
|---|---|---|---|
| `structure.NAME_DIVERGES` | `lfh_name != cd_name`（字节比较） | 直接 `bytes.__ne__` | 不做任何解码后比较（NFC/NFD 差异属 MOD-3） |
| `structure.CRC_DIVERGES` | `lfh_crc != cd_crc` | 仅当 `flags` bit 3 未置位时才比（data descriptor 场景 LFH 的 CRC 可为 0） | 置位 bit 3 且 LFH 为 0 → 不报，标 `evidence.data_descriptor=true` |
| `structure.SIZE_DIVERGES` | comp/uncomp size 不等 | 同 bit 3 豁免 | 同上 |
| `structure.FLAG_DIVERGES` | `lfh_flags != cd_flags` | 全 16 位比较；`evidence.bits` 列出差异位 | — |
| `structure.LFH_OVERLAP` | 两个 LFH 区间相交 | 排序后线性扫（`next.start < prev.end`） | 相邻不算相交；同一条目自身不算 |
| `structure.CD_COUNT_MISMATCH` | EOCD 计数 ≠ 实际 CD 条目数 | ZIP64 路径读 ZIP64 EOCD 计数 | 读不到 ZIP64 EOCD 而声明 0xFFFF → 报 `zip64_unsupported`（退出码 3） |

**依据纪律（硬）**：`precedent` 必填，取值只能是实现选择枚举：
`unzip_reads_cd` / `libzip_reads_cd` / `python_zipfile_reads_cd` / `libarchive_reads_lfh`。
**禁止**写"规范要求 LFH 与 CD 一致"（逐字检索无命中，见 `data/README.md` §1.4）。

**验收**：
- `mismatch_name.zip` → 恰有 1 条 `NAME_DIVERGES`，`lfhName=allowed.txt`、`cdName=evil.txt`；
- `alias_lfh.zip` → 断言具体项（构造时决定是 FLAG 还是 NAME）；
- `overlap.zip` → 恰有 1 条 `LFH_OVERLAP`，`evidence` 给出两组 `[start,end)`；
- `wrong_count.zip` → 恰有 1 条 `CD_COUNT_MISMATCH`，`evidence.declared` vs `evidence.actual`；
- **三工具行为断言进 CI**（本模块的"预言是否属实"自证）：Python `zipfile` 抛 `BadZipFile`、`unzip -o` stderr 含警告且落盘 `evil.txt`、`7z l` 取 `allowed.txt` 且 `Errors: 1`。
- `clean.zip` → 0 条 `structure.*`。

## MOD-2 编码推断与 Unicode path extra field（M2 骨架 / M5 收尾）

**输入**：条目原始名字节 + bit 11 + extra fields。**输出**：`encoding.candidates[]` / `upath` / `predictedNames`。

- 候选顺序**固定**：`UTF-8, CP437, GBK, CP932, CP949, CP1251`（`data/README.md` §4.4）。
- 可信度只由字节统计决定（`high` / `medium` / `low`），不用启发式随机。
- 0x7075：解析 `version(1) / name_crc32(4) / utf8_name`；**CRC 对 entry 原名字节校验**，通过才算覆盖有效；不通过 → finding `encoding.UPATH_CRC_MISMATCH` + 该条降级 `low`。
- 0x6375（Unicode Comment）与 0x0008（extended timestamp）**只记录不解释**。
- 预测规则按提取器固定（`unzip` → 0x7075 优先，否则 locale；`7z` → 多编码猜测；`python` → bit11 严格；`libarchive` → 自身转换表）。

**误报控制**：无法完整解码的候选**不出现**在候选列表里（不是列出来标 low）；`predictedNames` 对不可解码情形给 `null` + `reason`，不编造替代名。

**验收**：`zh_gbk.zip` 三提取器预测互不相同；`upath.zip` 7-Zip 出 `café.txt` 而 Python/unzip 出 `caf茅.txt`；`upath_badcrc.zip` 输出 `UPATH_CRC_MISMATCH` 且降级。

## MOD-3 跨平台落盘折叠（M3）

**输入**：MOD-1/2 得到的"每个提取器会写出的名字" + `--target`。**输出**：`collisions[]`。

| `ruleId` | 判定 |
|---|---|
| `collision.FILEDIR` | 同一路径既是文件又要求当目录（`a` 与 `a/b` 并存） |
| `collision.CASEFOLD` | 目标平台大小写下相撞 |
| `collision.NFC` | 归一化后相撞（macOS 做、Windows/Linux 不做） |
| `collision.TRIM` | 尾随空格/点裁剪后相撞（仅 Windows） |

**判定顺序固定**：FILEDIR → CASEFOLD → NFC → TRIM（同一对可命中多条，全部输出）。
**折叠表来源**：
- `windows`：**真实 NTFS `$UpCase`**（`data/platforms/ntfs-upcase.bin`）。**禁止 `str.lower()`/`casefold()`**。
- `macos`：UAX #15 + TN1150 + libfsapfs 观察，输出带 `evidence_strength: medium`。
- `linux`：不做大小写折叠；`/` 不可出现；长度按**字节**判。

**写序→存活者**：`writeOrder` = CD 顺序；`survivor` = 最后写入者；`verdict` ∈ {`overwritten`,`renamed`,`skipped`}。
**为什么这是差异点**：竞品只说"会冲突"，我们说"最后剩谁"（`case.zip` → `README.TXT`，内容 `LOWER`）。

**验收**：
- `case.zip --target windows` → 1 条 `CASEFOLD`，`survivor=README.TXT`；`macos`/`linux` 无 `CASEFOLD`（NTFS 与 macOS 的折叠差异见 §4.3）；
- `norm.zip --target windows` → **不得**报 NFC；`--target macos` → **必须**报 `collision.NFC`；
- 8 组字符对回归（`ı/I`、`ſ/S`、`ß/SS`、`ß/ss`、`İ/i`、`ǅ/Ǆ`、`ω/Ω` + 对照组）：真表结果与实测一致，且与 `casefold` 近似结果**不同**（这条同时证明"近似法为什么不能用"）。

## MOD-4 非法名与可访问性分级（M4）

**输入**：MOD-3 的"会写出的名字" + 目标平台表。**输出**：`entries[].accessibility` + `reasons[]` + `evidence[]`。

三级定义唯一表述在 `data/README.md` §4.2（`BLOCKED` / `WRITTEN_UNREADABLE` / `WRITTEN_TRUNCATED`），`OK` 是第四种取值但**不是级别**。

**分级算法**（顺序固定，先命中先返回；同时输出全部 `reasons`）：

```
1. 名字为空 / 仅为 "." ".." / 含 NUL         → BLOCKED
2. 目标=linux 且含 "/"                        → BLOCKED
3. 目标=windows 且含 < > : " / \ | ? * 或 0x00-0x1F → BLOCKED
4. 目标=windows 且 basename（去扩展名后）∈ 保留设备名 → WRITTEN_UNREADABLE
   保留名集合含：CON PRN AUX NUL COM1-9 LPT1-9 CLOCK$，以及上标 ¹²³ 变体
5. 目标=windows 且尾随空格/点存在 → WRITTEN_TRUNCATED
6. 组件超长（windows UTF-16 码元 > 255 或整路径 > 260；linux 字节 > NAME_MAX/PATH_MAX）→ WRITTEN_TRUNCATED
7. 其余 → OK
```

**不能只看第 5 步就判 TRUNCATED**：`CON.txt` 不违规、能写入、名字也没变，但应用层拿不到 —— 这正是
第三级的价值（`data/README.md` §1.3.2 三条实测）。

**`evidence` 固定枚举**（机读，`CON.txt` 必须三条齐）：`test_path_false` / `get_content_error` / `open_readable`。

**验收**：`reserved.zip` 的 `CON.txt`/`NUL.txt`/`aux.tar.gz` → `WRITTEN_UNREADABLE`（三证据齐）；
`trailing.zip` 的 `trailing. `、`trailingdot.` → `WRITTEN_TRUNCATED`；`colon:name.txt` → `BLOCKED`（Windows 非法字符）；
`trim.zip`（`readme.` + `readme`）→ 两者 `WRITTEN_TRUNCATED` 且触发 `collision.TRIM`。

## MOD-5 容器约定与长度预算（M5）

**输入**：entry 序列 + extra + method + 首文件字节。**输出**：`container.*` / `budget.*`。

| `ruleId` | 判定 | 依据 | 特别标注 |
|---|---|---|---|
| `container.MIMETYPE_NOT_FIRST` | EPUB/ODF 的 `mimetype` 不是 CD 首条目 | EPUB 3.3 §4.3.3 | — |
| `container.MIMETYPE_COMPRESSED` | `mimetype` method≠0 或加密位 | 同上 | — |
| `container.MIMETYPE_EXTRA` | `mimetype` 带 extra | 同上 + ODF 1.2 p3 §3.3 | — |
| `container.MIMETYPE_PADDING` | `mimetype` 内容前后有空白/padding | EPUB 3.3 | **ODF 上下文标 `inferred: true`**（原文未明文禁止尾随换行） |
| `container.UTF8_REQUIRED` | 容器要求 UTF-8 但 bit 11 未置位 | EPUB 3.3 §4.3.2 | — |
| `budget.PATH_OVER_260` | Windows 目标整路径 > 260（含终止 NUL） | `data/README.md` §4.6 | 与 `\\?\` 场景区分 |
| `budget.COMPONENT_OVER_255` | 单组件超限（Windows UTF-16 码元 / Linux 字节） | 同上 | 分平台判 |

**容器识别**：`mimetype` 条目存在 **且**（`META-INF/container.xml` 存在 **或** `mimetype` 内容为
`application/epub+zip` / `application/vnd.oasis.opendocument.*`）。识别不出 → **不做容器检查**，不猜。

**交叉验证纪律**：`epubcheck` / ODF validator 只做 XML 层与包文档语义，**不做 ZIP 层**；本文档与
README 必须逐字写清互补关系，**不得暗示"更强"**。

**验收**：`not_first.epub` / `compressed.epub` / `extra.epub` / `padding.epub` 各命中一个 code 且**互不串报**；
`long_path.zip` / `long_comp.zip` 分别命中；`clean.zip` → 0 条 `container.*`（零误报基线）。

## 模块落地顺序与依赖

```
M1: fixture + 真值 + 四工具对照 + $UpCase 取表
M2: zip_reader 完整化 → MOD-1 六条 → MOD-2 骨架（原始字节/bit11/extra）
M3: platforms 表接入 → MOD-3（含写序→存活者）
M4: MOD-4 + docs/rules.md
M5: MOD-5 + MOD-2 收尾 + 确定性导出
M6: 打包 + docs/divergence.md + 发布
```

**落地时同步改三处**：`capabilities.py` 的 `implemented` 翻 True、`plan/00` §三台账行、`plan/05` 状态表。
少一处 = 布局门 `LAYOUT.STATUS` / `LAYOUT.LEDGER` 红（这正是它被设计成这样做的原因）。
